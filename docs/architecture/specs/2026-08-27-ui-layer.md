# UI layer for `new_src/` — immediate-mode framework + migration of the existing screens

Date: 2026-08-27. Decision record: [ADR 0012](../adr/0012-immediate-mode-ui-layer.md).
Status: specification, not implemented.

Scope: introduce `new_src/ui/` as a real layer — an immediate-mode drawing +
input framework (`Ui`), per-frame view models, stateless per-screen view
functions — and migrate the screens that already work (HUD, loot list,
dialogs, view weapon) onto it without changing a pixel of their behaviour.
The menu screen is designed later, on top of the same framework, once
`docs/original-code/ui.md` carries its structure and geometry.

Two invariants drive everything below:

* **UI receives values and returns intents.** Mechanically checkable:
  `grep -rn "domain/game" new_src/ui/` must come back empty when this spec is
  done (it does not today: `new_src/ui/ViewWeapon.cpp:6-8` includes
  `domain/game/Game.h`, `Player.h`, `WeaponTable.h`).
* **Behaviour of migrated screens stays bit-identical.** The legacy screens
  draw whole 16 px rows (`DialogSystem::kLineH`, 3 visible loot rows,
  `new_src/core/LootSession.cpp:155-165`); the new scissor exists for NEW UI
  and must not be turned on for them (Deviation D1).

---

## 0. Layering rules for `new_src/ui/`

Allowed includes: `render/`, `render/gl/`, `text/`, `graphics/`, `io/`
(tables/localization data types only), and the standard library.

Forbidden: `domain/game/`, `domain/world/`, `core/`.

* `domain/*` — the invariant above.
* `core/` — `core/GameContext.h` already includes `ui/ViewWeapon.h`
  (`new_src/core/GameContext.h:14`); a `ui/ -> core/` edge would close a
  cycle. Today `new_src/ui/Hud.cpp:6` includes `core/AppContext.h` only to
  read resources; §2.1 replaces that with an injected reader functor.

`platform/` is also out: SDL knowledge stays on the producer side of
`UiInput` (§3).

## 1. GROUP 1 — plumbing: real scissor + window→canvas cursor mapping

Files: `new_src/render/gl/SpriteBatch.{h,cpp}`,
`new_src/render/Graphics2D.{h,cpp}`, `new_src/render/RenderBackend.{h,cpp}`,

### 1.1 `SpriteBatch` scissor

Public API (mirrors the proven `setBlendMode` shape — compare, `flush()`,
assign, `new_src/render/gl/SpriteBatch.cpp:145-149`):

```cpp
	// Latched by RenderBackend::applyViewport: the full letterboxed canvas
	// rect in drawable pixels. Needed because vertices are canvas-space and
	// the letterbox lives in the GL viewport.
	void setLetterbox(int x, int y, int w, int h);

	// Scissor in CANVAS coordinates (480x320, origin top-left). w<=0 || h<=0
	// clips everything away (an empty rect, NOT "no clip").
	void setScissorCanvas(int x, int y, int w, int h);
	void clearScissor();
	bool scissorActive() const { return scissorActive_; }
```

Implementation contract:

1. Both setters early-return when the requested state equals the current
   state (`scissorActive_` + `scissorRect_[4]` in canvas coords).
2. Otherwise `flush()` FIRST. Quads rasterize at flush time
   (`new_src/render/gl/SpriteBatch.cpp:170-215`); without the flush the
   already-batched quads would be clipped retroactively — the same class of
   bug as the viewport change guarded at
   `new_src/render/RenderBackend.cpp:41-43`.
3. Then convert and apply:

```
sx = letterboxW / 480.0f        // Window::kCanvasWidth
sy = letterboxH / 320.0f        // Window::kCanvasHeight
gx = letterboxX + (int)lroundf(x  * sx)
gy = letterboxY + (int)lroundf((320 - (y + h)) * sy)   // GL y is bottom-up
gw = max(0, (int)lroundf(w * sx))
gh = max(0, (int)lroundf(h * sy))
glEnable(GL_SCISSOR_TEST); glScissor(gx, gy, gw, gh);
```

   The `320 - (y + h)` flip is the axis that produced the "cutscene viewport
   slides down" defect; it is the same expression already used for the
   sub-viewport (`new_src/render/RenderBackend.cpp:50`:
   `gy = canvasVp_[1] + (int)((Window::kCanvasHeight - y - h) * scale)`).
4. `clearScissor()` → `flush()` then `glDisable(GL_SCISSOR_TEST)`.
5. `begin()` (`SpriteBatch.cpp:124-140`) resets: `scissorActive_ = false`,
   `glDisable(GL_SCISSOR_TEST)`. `end()` (`:142-146`) calls `flush()` (it
   already does) and then disables scissor, so no frame can leak a scissor
   into the next one.
6. `flush()` itself must NOT touch scissor state.
7. If `setScissorCanvas` is called while a sub-viewport is active (see 1.2),
   the result is undefined by design: log once to stderr and apply anyway.
   No caller in this spec does it.

### 1.2 `RenderBackend`

* `applyViewport` (`RenderBackend.cpp:31-39`) additionally calls
  `batch_.setLetterbox(vx, vy, vw, vh)`. `setCanvasViewport`
  (`:41-55`) does **not** change the latched letterbox — the letterbox stays
  the reference frame for scissor and for cursor mapping, and the world
  sub-viewport is a separate concern (ADR 0009).
* New read-only accessors (this is the requested "expose the inverse of
  `canvasVp_`"):

```cpp
	void letterboxRect(int& x, int& y, int& w, int& h) const;
	// Drawable-pixel point -> canvas point. Returns false when the point is
	// in the letterbox bars (cx/cy are still written, clamped is NOT done).
	bool drawableToCanvas(int px, int py, int& cx, int& cy) const;
```

  `drawableToCanvas`: `cx = (px - canvasVp_[0]) * 480 / canvasVp_[2]`,
  `cy = (py - canvasVp_[1]) * 320 / canvasVp_[3]`; the inside test is
  `0 <= cx < 480 && 0 <= cy < 320`. Guard `canvasVp_[2] <= 0`.

### 1.3 `Graphics2D`

`setClip`/`clearClip` become real:

```cpp
void Graphics2D::setClip(int x, int y, int w, int h) {
	clip stored as today; if (batch_) batch_->setScissorCanvas(x, y, w, h);
}
void Graphics2D::clearClip() { ... if (batch_) batch_->clearScissor(); }
```

Delete the WARNING blocks in `new_src/render/Graphics2D.h:36-42` and
`new_src/render/Graphics2D.cpp:17-29` and the two stale comments in
`new_src/ui/ViewWeapon.cpp:48,63`. **`ViewWeapon`'s hand clipping stays**
(Deviation D1): it trims the destination quad AND the source sub-rect, which
scissor cannot reproduce (scissor would also cut the magnified art
differently at the band edge). Do not "simplify" it.

No clip stack in `Graphics2D` — one level only. Nesting is the UI layer's job
(`Ui::pushClip`, §2.3).

### 1.4 `Window`

`Window::screenToCanvas` (`new_src/platform/Window.cpp:171-176`) has zero
callers and silently assumes drawable pixels. Replace it with:

```cpp
	// SDL window (screen) coordinates -> drawable pixels. Identity unless the
	// display is HiDPI (drawableWidth_ != winWidth_).
	void windowToDrawable(int wx, int wy, int& px, int& py) const;
```

`px = wx * drawableWidth_ / max(winWidth_,1)`, likewise y. The full
window→canvas path is then `Window::windowToDrawable` +
`RenderBackend::drawableToCanvas` — one transform, one owner each, no
duplicated letterbox math.

### 1.5 Acceptance (GROUP 1)

* Nothing changes on screen: title/intro, cinematics with their letterbox,
  the world band, the HUD panels, the loot list and dialog boxes look exactly
  as before (no clip caller exists yet).
* Temporary proof, shown to the user and then removed in the same group:
  wrap the loot-list body draw in `g.setClip(0, 0, 240, 320)` /
  `g.clearClip()`. The user must see the loot box cut in half vertically down
  the canvas centre — text and the red body ending mid-canvas, with the
  right half showing the world/HUD underneath — and after removing the two
  lines the loot list must look exactly as before again.
* Second temporary proof: `fprintf` the canvas coords of every mouse press;
  clicking the four canvas corners must print approximately (0,0), (479,0),
  (0,319), (479,319) in windowed AND fullscreen mode, and clicks in the
  letterbox bars must print "outside".

### 2.2 `ui/UiTypes.h` — ids, intents, input, result

```cpp
enum class UiId : int {
	None = 0,
	// HUD bottom bar (rects: docs/original-code/ui.md §1)
	HudSwitchLeft, HudSwitchRight, HudWeapon, HudPortrait, HudShield,
	HudHealth, HudKeys, HudSoftLeft, HudSoftCenter, HudSoftRight,

// What the UI reports. Every value must be translatable into the EXISTING
// Action queue (new_src/core/GameStates.h:26-27) — see §4.2.
enum class UiAction : int {
	None = 0,
	Menu, Automap, Back, PassTurn, Activate,
	ScrollUp, ScrollDown, ScrollHome, ScrollEnd,
	ListRow,          // index carries the row
};

enum class Nav : int { None, Up, Down, Left, Right, Activate, Cancel };

struct UiInput {
	int  cursorX = -1, cursorY = -1;   // canvas coords; <0 = no cursor

	bool released = false;             // release edge THIS frame

struct UiRect { int x = 0, y = 0, w = 0, h = 0;
	bool contains(int px, int py) const;

struct UiResult { UiAction action = UiAction::None; int index = -1; };
```

### 2.4 `ui/Ui.{h,cpp}` — primitives

`Ui` is a per-frame façade: it borrows `Graphics2D`, `Font`, `UiAssets`,
`UiState` and the frame's `UiInput`. It owns nothing and allocates nothing
per frame (the wrap cache lives in `UiState`).

```cpp
class Ui {
public:
	struct Env {
		Graphics2D* g = nullptr;
		const Font* font = nullptr;
		const UiAssets* assets = nullptr;
		UiState* state = nullptr;
	};
	void init(const Env& env);

	void beginFrame(const UiInput& in);  // latch input; no drawing
	void endFrame();                     // if (!in.down) state->activeId = None

	const UiInput& in() const { return in_; }
	Graphics2D& g() const { return *env_.g; }
	const UiAssets& art() const { return *env_.assets; }

	// ---- clipping (nested; intersects with the enclosing clip) ----
	static constexpr int kMaxClipDepth = 4;
	void pushClip(const UiRect& r);   // Graphics2D::setClip(intersection)
	void popClip();                   // restore parent clip or clearClip()

	// ---- hit testing ----
	bool isActive(UiId id) const;     // pressed and not yet released
	bool hover(const UiRect& r) const;

	// ---- primitives (all dumb: every constant comes from the caller) ----
	void panel(const UiRect& r, uint32_t fillArgb, uint32_t borderArgb = 0);
	void image(const Texture& tex, int x, int y, int anchorFlags);
	void imageRegion(const Texture& tex, int srcX, int srcY, int srcW, int srcH,
	                 int x, int y, int anchorFlags);
	void number3(const Texture& sheet, int x, int y, int space, int value,
	             bool slashMode);
	void label(const Text& t, int x, int y, int anchorFlags, int lineH = 16);
	void textRows(const Text& t, const short* lineIndex, int firstLine,
	              int rows, int x, int y, int lineH, int anchorFlags);
	int  textBlock(UiId cacheId, const Text& src, int x, int y, int widthPx,
	               int lineH, int firstLine, int rows, int anchorFlags);
	bool button(UiId id, const UiRect& r, const Texture& normal,
	            const Texture& active, int anchorFlags);
	bool buttonRect(UiId id, const UiRect& r);          // invisible hit area
	bool softKey(UiId id, const Text& label, int x, int y, int anchorFlags,
	             const UiRect& hit);
	int  listHit(UiId id, const UiRect& r, int rowH, int visibleRows);
	void scrollBar(int x, int y, int h, int topLine, int pageEnd,
	               int numLines, int viewLines);
	void face(const Texture& sheet, int x, int y, int rowH,
	          int health, int maxHealth);
	void weaponIcon(const Texture& sheet, int x, int y, int rowH, int weapon);
	void keys(const Texture& sheet, int x, int y, int rowH, int keysRow);

private:
	Env env_;
	UiInput in_;
	UiRect clipStack_[kMaxClipDepth];
	int clipDepth_ = 0;
};
```

Semantics and citations, primitive by primitive:

* `panel` — `Graphics2D::fillRect` + optional `drawRect`, ARGB unpacked the
  way the existing overlays do it (`new_src/core/LootSession.cpp:129-138`).
  Alpha byte of `fillArgb` is honoured; `borderArgb == 0` means no border.
* `image` / `imageRegion` — thin passthrough to
  `Graphics2D::drawImage/drawRegion` with the legacy anchor flags
  (`new_src/render/Graphics2D.h:21-27`; J2ME anchor numbering documented in
  `docs/original-code/ui.md` §1). Invalid textures are skipped silently
  (same as today).
* `number3` — port of `Hud::drawNumbers` (`docs/original-code/ui.md` §2,
  `src/Hud.cpp:1127-1152`): refuses `value >= 1000`; always three glyphs of
  10×20 from `sheet`; row = `20 * (9 - digit)`; x positions `x`,
  `x + space + 10`, `x + 2*space + 20`; no leading-zero suppression.
  `slashMode` is the weapon-13 rule: `d0 = value % 10`, `d1 = -1` (row
  `20*(9-(-1)) = 200` = the '/' glyph of the 11-row sheet), `d2 = 5`, third
  glyph still at `x + 2*space + 20`. This FIXES the current bug
  (`new_src/ui/Hud.cpp:577-593` drops the middle glyph, rendering "N5"
  instead of "N/5" — `docs/original-code/ui.md` §9 item 3).
* `label` — `Graphics2D::drawString(font, t, x, y, anchorFlags, lineH)`.
* `textRows` — `rows` calls of
  `drawString(..., lineH, lineIndex[i*2], lineIndex[i*2+1])`, i.e. exactly
  the loop at `new_src/core/LootSession.cpp:155-165`. Lines outside
  `[0, lineCount)` are skipped, not clamped.
* `textBlock` — wrap-on-demand paragraph: looks the wrap up in
  `UiState`'s cache keyed by `(&src, src.length(), widthPx, lineH)`; on a
  miss it wraps with `Text::wrap` (`new_src/text/Text.h:58-62`) using the
  char budget `widthPx / 9` (font advance 9, `new_src/text/Font.h:18-20`; the
  legacy budgets `(W-2)/9` and `(W-9)/9` live at
  `new_src/domain/game/DialogSystem.h:36-38` and stay in the caller's
  `widthPx`), fills a `<start,len>` table and then delegates to `textRows`.
  Returns the total line count so the caller can size a scrollbar.
  **`textBlock` is for NEW UI only**; migrated screens keep their own,
  already-verified wrap tables (Deviation D1).
* `button` — draws `isActive(id) ? active : normal` via `imageRegion` at
  `(r.x, r.y)` and hit-tests `r`. Returns true exactly once, on the release
  edge with the cursor inside (rule below).
* `buttonRect` — the same hit-test with no drawing, for widgets whose art the
  caller composes itself (the portrait plate = face + frame, the key sheet).
* `softKey` — `label(...)` plus the `hit` rect hit-test. The hit rect is a
  caller constant: the original bar has no measured hit boxes
  (`docs/original-code/ui.md` §6 gives only the text anchors (2,320)/(240,320)
  /(478,320)), so nothing is inferred here.
* `listHit` — returns `0..visibleRows-1` when the release edge lands inside
  row `i` of `r` (`rowH` each), else `-1`. Draws nothing: rows are drawn by
  the caller with `textRows`, which is what keeps the loot list identical.
* `scrollBar` — the MOVE of `DialogSystem::drawScrollBar`
  (`new_src/domain/game/DialogSystem.cpp:579-595`, port of
  `src/Canvas.cpp:1284-1315`), verbatim math including the
  `numLines == pageEnd` special case and the `uiImages` 7×7 caps at
  `(60,0)`/`(60,7)`. `kScrollTrack` / `kScrollThumb` colour constants move
  with it into `Ui.cpp`. Fixes the misplacement where `LootSession` reaches
  into the dialog system just to draw a scrollbar
  (`new_src/core/LootSession.cpp:167-169`).
* `face` — `imageRegion(sheet, 0, rowH*row, sheet.width(), rowH, x, y, TOP)`
  with `row = 4 - 5*health/max(maxHealth,1)`, clamped at 0
  (`docs/original-code/ui.md` §4, `src/Hud.cpp:695-699`). Formatting from
  passed-in values — permitted by the invariant.
* `weaponIcon` — the texY table of `docs/original-code/ui.md` §3
  (`0→0, 1→1, 2→2, 3,4→10, 5,6→11, 7→3, 8→4, 9→5, 10→6, 11→7, 12→8, 13→9,
  14→12, else→13`), 44 px rows; draws the icon only. Ammo digits are a
  separate `number3` call by the caller (the legacy coupling in
  `Hud::drawWeapon` hides the `showAmmo` rule inside the blit).
* `keys` — `imageRegion(sheet, 0, rowH*keysRow, sheet.width(), rowH, ...)`,
  `keysRow ∈ 0..3` computed by the model builder
  (`docs/original-code/ui.md` §5).

Hit-test rule, used by `button`/`buttonRect`/`softKey`/`listHit`:

```
if (in_.pressed && r.contains(cursor) && state->activeId == UiId::None)
	state->activeId = id;                       // press latched
bool fired = false;
if (in_.released && state->activeId == id) {
	fired = r.contains(cursor);                 // released outside = cancel
	state->activeId = UiId::None;
}
```

`isActive(id)` is `state->activeId == id && in_.down`, which is what selects
the `*_Active` sheets (`docs/original-code/ui.md` §1: "a highlighted button
only swaps the *_Active sheet — no position change").

`endFrame()` releases a stale `activeId` when the button is no longer held
(mouse released off-canvas, focus loss).

**No focus graph, no generic navigation.** Our UI is 1-D lists plus a few
fixed buttons; `Nav` moves a selected index that the screen session owns, and
buttons with no cursor get an explicit shortcut. Escape hatch, recorded on
purpose: a stick-driven virtual cursor would feed `cursorX/cursorY` and reuse
the hit-test path above unchanged — no new machinery.

## 3. GROUP 3 — input normalization

Files: `new_src/core/UiInputCollector.{h,cpp}` (new),
`new_src/core/GameLoop.cpp` (event lambda moves in),
`new_src/core/GameContext.{h,cpp}` (accepts the frame's `UiInput`).

One place turns SDL into `UiInput`:

```cpp
class UiInputCollector {
public:
	void beginFrame();                      // clears edges: pressed/released/nav/wheel
	void onEvent(const SDL_Event& ev, Window& w, RenderBackend& r);
	const UiInput& input() const { return in_; }
	// Key actions keep flowing to the existing queue: the collector reports
	// what it mapped and GameLoop pushes it, exactly as today.
	Action keyAction(const SDL_Event& ev) const;   // moved switch, verbatim
private:
	UiInput in_;
};
```

Mapping:

| SDL | `UiInput` |
|---|---|
| `SDL_MOUSEMOTION` | `windowToDrawable` + `drawableToCanvas` → `cursorX/Y`, `cursorValid` |
| `SDL_MOUSEBUTTONDOWN` (left) | `pressed = true; down = true;` + cursor update |
| `SDL_MOUSEBUTTONUP` (left) | `released = true; down = false;` + cursor update |
| `SDL_MOUSEWHEEL` | `wheel += ev.wheel.y` |
| `SDL_KEYDOWN` arrows / W,A,S,D | `nav = Up/Down/Left/Right` **and** the existing `Action` (both paths, no divergence) |
| `SDL_KEYDOWN` E / Return | `nav = Activate` |
| `SDL_KEYDOWN` Backspace | `nav = Cancel` |

The keyboard→`Action` switch (`new_src/core/GameLoop.cpp:38-50`) moves into
`keyAction` **verbatim**, including the debug `K` handling staying in
`GameLoop` (it is not an `Action`).

`GameLoop` per frame: `collector.beginFrame()` → `input().poll()` (callback
calls `collector.onEvent` and `ctx.queueAction(collector.keyAction(ev))`) →
tick → `ctx.setUiInput(collector.input())` before `ctx.render(app)`.

Gamepad: not implemented (there is no `SDL_GameController` anywhere in
`new_src/` today) and, unlike the rest of the project, it has no original to
be faithful to — the original was touch + soft keys. The only surface it will
ever need is `Nav` + a virtual cursor; nothing else is designed now.

### 3.1 Acceptance (GROUP 3)

## CORRECTION 2026-08-28 (orchestrator) — deviation D3 was wrong

D3 assumed the switch arrows and the soft-key labels are separate widgets with no
established semantics. The original pins both, and they are **the same button**:

- `src/Hud.cpp:67-71` registers hud button **0 at (0,256,52,64)** and **1 at
  (428,256,52,64)**. The `btnSwitchRight`/`btnSwitchLeft` names are a misnomer;
  nothing is swapped in effect.
- `src/TouchController.cpp:550-570` draws `imgSwitchLeft*` at (9,268) and the
  "Menu" label at (2,320) **both keyed on button 0's `highlighted`**; likewise
  right/(438,268)/(478,320) from button 1. So the arrow art IS the soft key's
  pressed state.
- `src/Hud.cpp:1300-1320`: button 0 -> `ACTION_MENU`, button 1 -> `ACTION_AUTOMAP`.

Implemented that way in G4 (one `UiId` per side), which also removes an overlap the
two-widget reading would have created: the left hit rect (0,256,52,64) fully
contains the "Menu" label box. `UiId::HudSwitchLeft/Right` are consequently unused.

From the same handler, for whoever wires the remaining highlights: the **portrait**
is `ACTION_PASSTURN` (219,264,42,36), the **weapon icon** is `ACTION_NEXTWEAPON`,
and shield / health / keys are ITEMS_DRINKS / ITEMS / QUESTLOG. There is no
weapon-switch action on the arrows at all.


## DEVIATION 2026-08-28 (user request) — soft-key hit rects narrowed to the arrow icons
