### Rewrite
- `new_src/core/PlayerActions.cpp:272`: `if (weapon2 >= 0) { elected = electFireTarget(...) }` —
  with no weapon nothing is elected, so the crate branch (`:280-284`) cannot fire; the script
  then runs and disables event 91 → crate solid forever, re-use runs nothing new. Exactly the log.
  The code even documents it: "shortcut: `elected` is only filled when weapon2 >= 0 … upgrade if
  an unarmed state becomes reachable in play" (`PlayerActions.cpp:314-316`). It is reachable.
- Even without that guard, `Targeting.cpp:149-154` would drop the crate: `weaponDef(-1)` returns
  an all-zero row (`Combat.cpp:103-109` → tables), `rangeMax 0`, `1 > 0`.
- `Targeting.cpp:41` `checkWeaponMask(-1, 2)` is `1 << -1`, UB in C++ — must be guarded too.
- Everything else matches the original: trace mask 13997, crate centre position, Chebyshev²
  `distFrom`, election order, `openCrate` = param + unlink.

## Verdict

**Rewrite bug (conditional on the player being unarmed, which the HUD/log should confirm —
before visiting the sergeant at (9,19) on map00 the player has no weapon).** The original code
is UB at this exact point; the rewrite resolved the UB as "never open", which leaves a looted
crate permanently solid. Resolve it as "open" (range gate skipped when `weapon < 0`).
If the player DID hold a weapon in the reported run, this explanation does not apply and the
election must be logged (`elected.eType/eSubType/electedDist`) to find the real cause.

## Fix prescription

1. `new_src/core/PlayerActions.cpp:272-276` — always elect:
   `elected = env_.targeting->electFireTarget(weapon2); electedDist = …;` (remove the
   `if (weapon2 >= 0)` wrapper). The fire block stays gated by `weapon2 >= 0` (`:329`). Side
   effect, faithful: the secret push wall (`:317-322`, legacy `:461-466`, no weapon check) also
   works unarmed — delete the shortcut comment at `:314-316`.
2. `new_src/domain/game/Targeting.cpp:41` —
   `const bool melee = weapon >= 0 && Combat::checkWeaponMask(weapon, 2);`
   (legacy `1 << -1` is UB; on ARM/x86 it yields 0x80000000 → not melee).
3. `new_src/domain/game/Targeting.cpp:149-152` — add `weapon >= 0 &&` to the eType-10 range
   gate, with a one-line comment: deviation, legacy reads `weapons[-6]` (UB,
   `src/PlayingInputHandler.cpp:379`); unarmed = no range gate so an adjacent crate opens.
   Other `weapon` uses in `electFireTarget` (`== 1`, `== 2`) are safe with -1.
