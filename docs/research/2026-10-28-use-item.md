## Key findings
- `useItem(n)`: n = inventory slot (`INV_*`); slot 22 = holy water paid from `ammo[3]`
  (`src/Player.cpp:801-806,935-944`). Single caller: `MenuSystem::select` actions 20/21
  (`src/MenuSystem.cpp:3149-3151`), reached via list row action 24 → confirm screen 77
  ("Use %01?", menu str 184) (`:3188-3197`, `:2047-2059`).
- Amounts/durations hard-coded in the switch (`src/Player.cpp:810-948`); `entities.bin` holds
  only name/description string ids.
- Success tail: sound 1124 (`use_item.wav`), `--inventory[n]` unless holy water, then
  `game->advanceTurn()` unless Smoothie (`src/Player.cpp:950-958`). So use = a full turn;
  `select` then calls `snapMonsters(true)` so the monster phase resolves inside the menu
  (`src/MenuSystem.cpp:3156-3157`, `src/Game.cpp:2391-2431`).
- Failure → no sound/consume/turn; menu shows data screen 79 (health), 80 (armor),
  81 (drinks), 82 (holy water) (`src/MenuSystem.cpp:3165-3177`).
- Health: +20 Snack, +80 Health Pack, clamp to max HP (no overheal, `src/CombatEntity.cpp:80-82`),
  message common 111 "Gained %01 health" (`src/Player.cpp:445-449`). Armor: +50 Flak Jacket,
  +10 Armor Shard, clamp 200, refuse at ≥200, no message (`src/Player.cpp:1933-1946`).
- Drinks → `addStatusEffect(effect, amount, turns)` with turns 31/21/11/3 = 30/20/10/2
  effective turns (decrement happens in the same use's advanceTurn; removal at turns==1,
  `src/Player.cpp:1458-1472`). Amounts stack up to 3 times (1 for antifire/poison), duration
  resets on re-use (`src/Player.cpp:1574-1594`).
- Table (slot: effect): 0 Energy Blast FORTITUDE+20 (max HP) + heal 20; 1 Focus Juice FOCUS+5;
  2 Super Quench ANTIFIRE 10t + remove FIRE; 3 Power Punch ANGER 25% + STRENGTH+20;
  4 Snake Venom WP_POISON 10 for 10t; 5 Youth Serum REGEN 5 HP/turn; 6 Caffeine Block DEF+25;
  7 Diet Might AGI+25; 8 Smoothie HASTE 20t, free action; 9 Monster Shot ANGER 100%;
  10 Hell Knight Sweat AGI+25, ANGER 25%, DEF+25, FOCUS+5; 22 Holy Water heal 25 + FEAR 2t
  (−25 holy-water ammo); 23 Pack → `return true` no-op; others false.
- Effect index trap: `STATUS_EFFECT_*` names for 2/5/6 differ from `BUFF_*`; translate maps
  effect j → buff j (`src/Player.cpp:1511-1515`), so BUFF_* meaning (HASTE/STRENGTH/AGILITY)
  is the behaviour.
- No quick-use and no auto-use: only menu openers (`src/PlayingInputHandler.cpp:159-178`,
  `src/InputEventController.cpp:79-86`, touch ids 4/5 `src/Hud.cpp:1346-1351`).

## Gap list vs new_src (as of 2026-10-28)
- `new_src/domain/game/Player.h:119` `addHealth` exists (same refusal/clamp logic,
  `new_src/domain/game/Player.cpp:204-214`) but emits no "Gained %01 health" message (111)
  and has no `b` (quiet) flag needed by regen.
- `new_src/domain/game/Player.h:132` `addArmor` returns `void`; useItem needs the bool
  (false at armor ≥ 200).
- No `statusEffects[54]` / `numStatusEffects` / `buffs[30]` / `numbuffs`, no
  add/remove/update/translateStatusEffects, no `updateStats()` (base + buffs).
- `new_src/domain/game/Game.cpp:324-340` `advanceTurn` hard-codes `monstersTurn = 1`
  (haste parity absent) and has no `player.advanceTurn()` (status tick, regen, fire/cold DoT).
- No `useItem`; `new_src/core/MenuSession.cpp:464-468` disables ACTION_CONFIRMUSE; no
  MENU_ITEMS_CONFIRM (77) or message screens 79-82; no sound system (use_item.wav).
- Buff consumers absent: anger % in damage (`src/CombatEntity.cpp:337-339`), antifire,
  fear AI goal (`src/Entity.cpp:541`), poison monsterEffects (`src/Combat.cpp:172-173`),
  haste movement/anim speed-ups. HUD buff box (`src/Player.cpp:1209-1260`, `Icons_Buffs.bmp`).
- Minimal port that already makes items usable: health/armor slots (16,17,11,12) + holy
  water health half need only `useItem` + bool `addArmor` + message 111 + the turn advance +
  confirm screen. Drinks need at least the statusEffects planes, add/translate/update,
  `updateStats`, the per-turn tick in Player advanceTurn; their gameplay effect needs the
  consumers above; visibility needs the HUD buff box.
