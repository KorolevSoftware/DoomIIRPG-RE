## Evidence (key points)
* Names: `GetSaveFile` `src/Game.cpp:3690-3750` → FWORLD, CONFIGFILENAME,
  BRIEFPLAYER, FULLPLAYER, SB_1..SB_10. Path `"Doom2rpg.app/"+name`
  (`src/JavaStream.h:10`, `src/JavaStream.cpp:93-95,224-226`, `src/Game.cpp:3752-3768`).
* IO is host-endian memcpy (`src/JavaStream.cpp:9-24`), little-endian in practice.
* Manual save: `ACTION_SAVE` → `saveState(3|0x80)` (`src/MenuSystem.cpp:3039-3049`);
  `ST_SAVING` → `Game::saveState(loadMapID, loadMapID, destX, destY, destAngle,
  viewPitch, prevX, prevY, saveX, saveY, saveZ, saveAngle, savePitch, type)`
  (`src/Canvas.cpp:871`) → config + FULLPLAYER + FWORLD (`src/Game.cpp:2059-2117`).
* Save&Quit = 67 (`src/MenuSystem.cpp:3114`), Main-menu-save = 7 (`:3200`).
* Config v11 with `0xDEADBEEF` trailer (`src/Game.cpp:1913-1975`); 791 bytes.
  `saveEmptyConfig` is shorter (no vibration/deadzone/isInit/keybinds,
  `src/Game.cpp:2359-2366`) — port bug, `loadConfig` would fail its marker check.
* Player record: 34-byte header (`src/Game.cpp:2155-2171`) + 271 bytes
  (`src/Player.cpp:1351-1420`), +108 with status effects, more if familiar.
* `loadState` re-derives `spawnParam` from saved view coords (tile + 45° dir),
  `src/Game.cpp:2209-2211`, so the exact sub-tile position is not restored.
* `hasSavedState` = config v11 && BRIEFPLAYER && FULLPLAYER && any SB_n
  (`src/Game.cpp:2249-2268`). FWORLD not required.
* Load type = `recentBriefSave ? 2 : 1` (`src/LoadingManager.cpp:753-760`);
  restart = 2 (`src/MenuSystem.cpp:3106`).
* Save Game item disabled when `inventory[18] == 0` (`src/MenuSystem.cpp:1560-1562`).
* Strings: 3:194 "Loading Game…", 3:196 "Saving Game…", 0:38 "Game Saved",
  0:39 / 3:195 "Game Loaded", 3:107 "This will erase your saved game. Are you
  sure?", 3:134 "Restart Level?", 3:135 "Save & Quit?", 3:136 "Load Game?",
  3:137 "You will lose all unsaved progress. Are you sure?".
